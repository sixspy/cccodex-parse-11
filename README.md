# cc-parse-lab

数据工程产品线：**页面与文件解析入库台**（Django + Jinja 多页 + SQLite）。

双源合并：主份与次份各自解析成功后，按合并键配对；同键不同值按已锁定的冲突策略裁定，裁定过程留进冲突匣，合并收尾后才允许落档。

## 规则

- **双份先齐**：主份、次份都须解析成功，单份未齐不能合并。
- **合并键必填**：合并键空着禁止开跑；行内缺键的行进冲突匣，不静默丢弃。
- **冲突策略当天锁定**：同键不同值按策略裁定，策略一经锁定当天不得更换。
  - `整行失败`：该行不进合并结果，整行进冲突匣。
  - `留主份`：保留主份值，旁注次份差异（`_resolution` / `_note`）。
- **处理须一致**：合并请求带的处理与锁定策略不一致时拦下，页面提示「合并冲突处理偏了」。
- **合并收尾才可落档**：未合并或合并中禁止落档。
- **先到先得**：并发合并只成先到者，后到者记「合并争用失败」并在详情可见。

## 页面

- 列表：主份条数、次份条数、冲突数、处理名、状态。
- 详情：双源分别解析、策略锁定、合并执行；冲突匣可展开查看主/次份行内容；合并争用失败留痕。
